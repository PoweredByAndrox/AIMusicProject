# Документ требований: Продвинутая система музыкального плеера

## Введение

Продвинутая система музыкального плеера — это расширение существующей системы музыкальных рекомендаций, добавляющее полнофункциональный аудиоплеер с управлением очередью и плейлистами, систему рейтинга фрагментов с комментариями, гранулярную 5-звёздочную систему оценки треков и умный режим радио с рекомендациями в реальном времени.

## Глоссарий

- **Player**: Аудиоплеер с управлением очередью воспроизведения и режимами повтора/перемешивания
- **Queue**: Очередь воспроизведения — упорядоченный список треков для последовательного проигрывания
- **Playlist**: Именованная коллекция треков, созданная пользователем или сгенерированная ИИ
- **AI_Playlist_Generator**: Компонент для автоматической генерации плейлистов на основе предпочтений
- **Crossfade**: Плавный переход между треками с наложением звука
- **Fragment_Rating**: Оценка конкретного временного диапазона внутри трека (лайк/дизлайк)
- **Fragment_Comment**: Текстовый комментарий к фрагменту с объяснением оценки
- **Waveform_Overlay**: Визуальное отображение оценённых сегментов на форме волны
- **Track_Rating**: 5-звёздочная оценка трека (1-5 звёзд)
- **Rating_History**: История изменений оценок пользователя
- **Smart_Radio**: Режим автоматического подбора треков на основе текущего воспроизведения
- **Recommendation_Engine**: Движок рекомендаций, учитывающий рейтинги, фрагменты и историю
- **Skip_Tracker**: Компонент отслеживания пропусков треков для обучения предпочтениям
- **User_Preference**: Пользовательские настройки для трека (громкость, последняя позиция)
- **ML_Fragment_Analyzer**: ML-компонент для анализа паттернов в оценённых фрагментах
- **Theme_System**: Система управления темами оформления (тёмная/светлая)
- **Animation_System**: Система анимаций и переходов интерфейса
- **Visualizer**: Компонент визуализации аудио в реальном времени
- **Page_Transition**: Анимированные переходы между страницами приложения
- **AI_DJ_Analyzer**: Компонент анализа треков для DJ-функций (ключ, BPM, энергия, точки входа/выхода)
- **AI_DJ_Matcher**: Компонент подбора гармонически совместимых треков по Camelot Wheel
- **Beatmatcher**: Компонент синхронизации битов между треками с time-stretching
- **AI_DJ_Transition**: Компонент создания профессиональных переходов с наложением
- **AI_DJ_Automix**: Компонент автоматического создания DJ-миксов
- **AI_DJ_Live**: Режим реального времени для автоматического DJ-микширования
- **Camelot_Wheel**: Система обозначения музыкальных ключей для гармонического микширования (1A-12A, 1B-12B)

## Требования

### Требование 1: Базовый аудиоплеер с очередью

**User Story:** Как пользователь, я хочу воспроизводить музыку с управлением очередью, чтобы слушать треки в нужном порядке.

#### Критерии приёмки

1. WHEN пользователь добавляет трек в очередь THEN THE Player SHALL добавить трек в конец Queue
2. WHEN пользователь добавляет трек "воспроизвести следующим" THEN THE Player SHALL вставить трек после текущего в Queue
3. WHEN текущий трек заканчивается THEN THE Player SHALL автоматически начать воспроизведение следующего трека из Queue
4. WHEN пользователь удаляет трек из очереди THEN THE Player SHALL удалить трек из Queue без прерывания воспроизведения
5. WHEN пользователь очищает очередь THEN THE Player SHALL удалить все треки из Queue кроме текущего
6. THE Player SHALL отображать текущую Queue с возможностью перетаскивания для изменения порядка
7. WHEN пользователь дважды кликает на трек в Queue THEN THE Player SHALL начать воспроизведение этого трека

### Требование 2: Режимы воспроизведения

**User Story:** Как пользователь, я хочу использовать режимы перемешивания и повтора, чтобы разнообразить прослушивание.

#### Критерии приёмки

1. WHEN пользователь включает режим Shuffle THEN THE Player SHALL воспроизводить треки из Queue в случайном порядке
2. WHEN пользователь выключает режим Shuffle THEN THE Player SHALL вернуться к исходному порядку Queue
3. WHEN пользователь включает режим Repeat_All THEN THE Player SHALL повторять всю Queue после завершения
4. WHEN пользователь включает режим Repeat_One THEN THE Player SHALL повторять текущий трек бесконечно
5. WHEN пользователь выключает режим Repeat THEN THE Player SHALL остановиться после последнего трека в Queue
6. THE Player SHALL отображать текущее состояние режимов Shuffle и Repeat в интерфейсе

### Требование 3: Crossfade между треками

**User Story:** Как пользователь, я хочу плавные переходы между треками, чтобы создать непрерывный поток музыки.

#### Критерии приёмки

1. WHERE Crossfade включён THEN THE Player SHALL начинать воспроизведение следующего трека за N секунд до окончания текущего
2. WHERE Crossfade включён THEN THE Player SHALL плавно уменьшать громкость текущего трека и увеличивать громкость следующего
3. THE Player SHALL позволять настраивать длительность Crossfade от 0 до 12 секунд
4. WHEN Crossfade выключен THEN THE Player SHALL воспроизводить треки последовательно без наложения
5. IF следующий трек короче длительности Crossfade THEN THE Player SHALL адаптировать длительность перехода

### Требование 4: Сохранение пользовательских настроек трека

**User Story:** Как пользователь, я хочу сохранять индивидуальные настройки для каждого трека, чтобы не настраивать их повторно.

#### Критерии приёмки

1. WHEN пользователь изменяет громкость для трека THEN THE User_Preference SHALL сохранить настройку громкости
2. WHEN пользователь останавливает воспроизведение THEN THE User_Preference SHALL сохранить текущую позицию
3. WHEN пользователь возобновляет воспроизведение трека THEN THE Player SHALL предложить продолжить с сохранённой позиции
4. THE User_Preference SHALL хранить настройки в базе данных с привязкой к track_id
5. WHEN трек удаляется THEN THE System SHALL удалить связанные User_Preference

### Требование 5: Создание и управление плейлистами

**User Story:** Как пользователь, я хочу создавать и редактировать плейлисты, чтобы организовывать музыку по своему вкусу.

#### Критерии приёмки

1. WHEN пользователь создаёт плейлист THEN THE Playlist_Manager SHALL создать запись с названием и описанием
2. WHEN пользователь добавляет трек в плейлист THEN THE Playlist_Manager SHALL добавить связь трека с плейлистом
3. WHEN пользователь удаляет трек из плейлиста THEN THE Playlist_Manager SHALL удалить связь без удаления трека
4. WHEN пользователь удаляет плейлист THEN THE Playlist_Manager SHALL удалить плейлист и все связи с треками
5. THE Playlist_Manager SHALL позволять переименовывать плейлисты и изменять описание
6. THE Playlist_Manager SHALL позволять изменять порядок треков в плейлисте перетаскиванием
7. WHEN пользователь воспроизводит плейлист THEN THE Player SHALL загрузить все треки плейлиста в Queue

### Требование 6: AI-генерация плейлистов

**User Story:** Как пользователь, я хочу автоматически генерировать плейлисты на основе моих предпочтений, чтобы открывать новую музыку.

#### Критерии приёмки

1. WHEN пользователь запрашивает AI-плейлист THEN THE AI_Playlist_Generator SHALL использовать Preference_Model для выбора треков
2. THE AI_Playlist_Generator SHALL учитывать 5-звёздочные рейтинги треков при генерации
3. THE AI_Playlist_Generator SHALL учитывать оценки фрагментов при генерации
4. THE AI_Playlist_Generator SHALL позволять указывать параметры: длительность, жанр, настроение, BPM-диапазон
5. WHEN AI-плейлист сгенерирован THEN THE System SHALL сохранить его как обычный плейлист с пометкой "AI-generated"
6. IF Preference_Model не обучена THEN THE AI_Playlist_Generator SHALL использовать только фильтры по характеристикам

### Требование 7: Рейтинг фрагментов (лайк/дизлайк)

**User Story:** Как пользователь, я хочу отмечать конкретные временные диапазоны в треке как понравившиеся или не понравившиеся, чтобы система лучше понимала мои предпочтения.

#### Критерии приёмки

1. WHEN пользователь выделяет область на waveform и ставит лайк THEN THE Fragment_Rating SHALL создать фрагмент с is_liked=true
2. WHEN пользователь выделяет область на waveform и ставит дизлайк THEN THE Fragment_Rating SHALL создать фрагмент с is_liked=false
3. WHEN пользователь изменяет оценку фрагмента THEN THE Fragment_Rating SHALL обновить значение is_liked
4. WHEN пользователь удаляет оценку фрагмента THEN THE Fragment_Rating SHALL удалить запись из базы данных
5. THE Waveform_Overlay SHALL отображать лайкнутые фрагменты зелёным цветом
6. THE Waveform_Overlay SHALL отображать дизлайкнутые фрагменты красным цветом
7. WHEN фрагмент оценён THEN THE System SHALL поставить его в очередь на ML-анализ эмбеддинга

### Требование 8: Комментарии к фрагментам

**User Story:** Как пользователь, я хочу добавлять текстовые комментарии к оценённым фрагментам, чтобы объяснять причину оценки.

#### Критерии приёмки

1. WHEN пользователь добавляет комментарий к фрагменту THEN THE Fragment_Comment SHALL сохранить текст с привязкой к fragment_id
2. THE Fragment_Comment SHALL поддерживать текст до 500 символов
3. WHEN пользователь редактирует комментарий THEN THE Fragment_Comment SHALL обновить текст
4. WHEN пользователь удаляет комментарий THEN THE Fragment_Comment SHALL удалить запись
5. WHEN пользователь наводит курсор на фрагмент THEN THE Waveform_Overlay SHALL отобразить комментарий во всплывающей подсказке
6. THE System SHALL позволять фильтровать фрагменты по наличию комментария

### Требование 9: Влияние фрагментов на рекомендации

**User Story:** Как пользователь, я хочу чтобы мои оценки фрагментов влияли на рекомендации, чтобы получать более точные предложения.

#### Критерии приёмки

1. WHEN Recommendation_Engine генерирует рекомендации THEN THE System SHALL учитывать эмбеддинги лайкнутых фрагментов как положительные примеры
2. WHEN Recommendation_Engine генерирует рекомендации THEN THE System SHALL учитывать эмбеддинги дизлайкнутых фрагментов как отрицательные примеры
3. THE Recommendation_Engine SHALL взвешивать фрагменты пропорционально их длительности
4. WHEN трек содержит и лайкнутые и дизлайкнутые фрагменты THEN THE Recommendation_Engine SHALL учитывать оба типа раздельно
5. THE ML_Fragment_Analyzer SHALL выявлять паттерны в оценённых фрагментах (инструменты, переходы, структура)

### Требование 10: Визуализация оценённых сегментов

**User Story:** Как пользователь, я хочу видеть все оценённые сегменты на форме волны, чтобы быстро ориентироваться в своих отметках.

#### Критерии приёмки

1. WHEN трек открыт THEN THE Waveform_Overlay SHALL отобразить все оценённые фрагменты поверх waveform
2. THE Waveform_Overlay SHALL использовать полупрозрачные цветные области для отображения фрагментов
3. THE Waveform_Overlay SHALL отображать иконки лайка/дизлайка на границах фрагментов
4. WHEN пользователь кликает на оценённый фрагмент THEN THE Player SHALL воспроизвести этот фрагмент
5. THE Waveform_Overlay SHALL поддерживать переключение видимости оценённых сегментов
6. WHEN фрагменты перекрываются THEN THE Waveform_Overlay SHALL отображать их с разной прозрачностью

### Требование 11: 5-звёздочная система оценки треков

**User Story:** Как пользователь, я хочу оценивать треки по 5-звёздочной шкале, чтобы более точно выражать своё отношение к музыке.

#### Критерии приёмки

1. WHEN пользователь устанавливает рейтинг трека THEN THE Track_Rating SHALL сохранить значение от 1 до 5 звёзд
2. WHEN пользователь изменяет рейтинг THEN THE Track_Rating SHALL обновить значение и записать в Rating_History
3. WHEN пользователь удаляет рейтинг THEN THE Track_Rating SHALL установить значение в NULL
4. THE System SHALL отображать рейтинг трека в библиотеке и плеере
5. THE System SHALL позволять фильтровать треки по рейтингу (например, "4 звезды и выше")
6. THE Track_Rating SHALL заменить бинарный is_liked для треков

### Требование 12: Вес рейтингов в рекомендациях

**User Story:** Как пользователь, я хочу чтобы 5-звёздочные рейтинги имели больший вес в рекомендациях, чем бинарные лайки фрагментов.

#### Критерии приёмки

1. WHEN Recommendation_Engine обучает Preference_Model THEN THE System SHALL использовать рейтинг как вес примера
2. THE Recommendation_Engine SHALL интерпретировать 5 звёзд как сильный положительный сигнал (вес 1.0)
3. THE Recommendation_Engine SHALL интерпретировать 1 звезду как отрицательный сигнал (вес -0.5)
4. THE Recommendation_Engine SHALL интерпретировать 3 звезды как нейтральный сигнал (вес 0.0)
5. THE Recommendation_Engine SHALL использовать линейную интерполяцию для промежуточных значений
6. WHEN трек имеет и рейтинг и оценённые фрагменты THEN THE Recommendation_Engine SHALL комбинировать оба сигнала

### Требование 13: Отображение рейтингов

**User Story:** Как пользователь, я хочу видеть средний рейтинг и свой рейтинг для каждого трека, чтобы ориентироваться в качестве музыки.

#### Критерии приёмки

1. THE Library_UI SHALL отображать пользовательский рейтинг для каждого трека
2. THE Library_UI SHALL отображать средний рейтинг трека (для будущей многопользовательской версии)
3. THE Player SHALL отображать интерактивный виджет рейтинга с 5 звёздами
4. WHEN пользователь наводит курсор на звезду THEN THE Rating_Widget SHALL подсвечивать звёзды до текущей
5. THE Rating_Widget SHALL поддерживать половинные звёзды для отображения среднего рейтинга

### Требование 14: История рейтингов

**User Story:** Как пользователь, я хочу видеть историю изменений своих рейтингов, чтобы отслеживать эволюцию своих предпочтений.

#### Критерии приёмки

1. WHEN пользователь изменяет рейтинг THEN THE Rating_History SHALL записать: track_id, old_rating, new_rating, timestamp
2. THE Rating_History SHALL хранить все изменения рейтингов без ограничения по времени
3. THE System SHALL предоставлять страницу просмотра Rating_History с фильтрацией по дате и треку
4. THE Rating_History SHALL отображать тренды изменения рейтингов (повышение/понижение)
5. WHEN трек удаляется THEN THE System SHALL сохранить Rating_History для аналитики

### Требование 15: Умное радио — базовый режим

**User Story:** Как пользователь, я хочу включить режим умного радио, чтобы система автоматически подбирала треки на основе текущего воспроизведения.

#### Критерии приёмки

1. WHEN пользователь включает Smart_Radio THEN THE System SHALL автоматически добавлять треки в Queue
2. WHEN Queue содержит менее 3 треков THEN THE Smart_Radio SHALL добавить новые рекомендованные треки
3. THE Smart_Radio SHALL использовать эмбеддинг текущего трека для поиска похожих
4. THE Smart_Radio SHALL учитывать 5-звёздочные рейтинги при выборе треков
5. THE Smart_Radio SHALL учитывать оценки фрагментов при выборе треков
6. WHEN пользователь выключает Smart_Radio THEN THE System SHALL прекратить автоматическое добавление треков

### Требование 16: Учёт истории прослушивания

**User Story:** Как пользователь, я хочу чтобы умное радио учитывало мою историю прослушивания, чтобы не повторять недавно проигранные треки.

#### Критерии приёмки

1. THE Smart_Radio SHALL исключать треки, воспроизведённые за последние 2 часа
2. THE Smart_Radio SHALL снижать приоритет треков, воспроизведённых за последние 24 часа
3. THE Listening_History SHALL записывать: track_id, timestamp, duration_played, completed
4. THE System SHALL хранить Listening_History за последние 30 дней
5. WHEN пользователь явно запрашивает трек THEN THE Smart_Radio SHALL игнорировать ограничение по истории

### Требование 17: Контролы "Больше/Меньше такого"

**User Story:** Как пользователь, я хочу давать обратную связь во время воспроизведения, чтобы корректировать рекомендации в реальном времени.

#### Критерии приёмки

1. WHEN пользователь нажимает "Больше такого" THEN THE Smart_Radio SHALL увеличить вес текущего трека в рекомендациях
2. WHEN пользователь нажимает "Меньше такого" THEN THE Smart_Radio SHALL уменьшить вес текущего трека в рекомендациях
3. THE Smart_Radio SHALL немедленно пересчитать следующие рекомендации после обратной связи
4. THE System SHALL сохранять обратную связь для обучения Preference_Model
5. THE Player SHALL отображать кнопки "Больше такого" и "Меньше такого" в режиме Smart_Radio

### Требование 18: Отслеживание пропусков

**User Story:** Как пользователь, я хочу чтобы система учитывала пропущенные треки, чтобы не рекомендовать нежелательную музыку.

#### Критерии приёмки

1. WHEN пользователь пропускает трек в первые 30 секунд THEN THE Skip_Tracker SHALL записать событие пропуска
2. THE Skip_Tracker SHALL хранить: track_id, timestamp, position_at_skip, source (queue/radio/playlist)
3. WHEN трек пропущен 3+ раза THEN THE Smart_Radio SHALL значительно снизить его приоритет
4. THE Recommendation_Engine SHALL использовать данные Skip_Tracker как отрицательный сигнал
5. THE System SHALL отображать статистику пропусков в информации о треке

### Требование 19: Автоматическое добавление в очередь

**User Story:** Как пользователь, я хочу чтобы умное радио автоматически поддерживало очередь заполненной, чтобы музыка не прерывалась.

#### Критерии приёмки

1. WHILE Smart_Radio активен THEN THE System SHALL поддерживать минимум 5 треков в Queue
2. THE Smart_Radio SHALL добавлять треки асинхронно, не блокируя воспроизведение
3. THE Smart_Radio SHALL разнообразить рекомендации, избегая треков одного исполнителя подряд
4. WHEN пользователь вручную добавляет трек в Queue THEN THE Smart_Radio SHALL учитывать его при следующих рекомендациях
5. THE Smart_Radio SHALL отображать индикатор "Подбираю следующие треки..." при генерации

### Требование 20: ML-обучение на паттернах фрагментов

**User Story:** Как пользователь, я хочу чтобы система обучалась на паттернах моих оценённых фрагментов, чтобы понимать какие музыкальные элементы мне нравятся.

#### Критерии приёмки

1. THE ML_Fragment_Analyzer SHALL извлекать характеристики из оценённых фрагментов (спектральные, ритмические, тональные)
2. THE ML_Fragment_Analyzer SHALL кластеризовать лайкнутые фрагменты для выявления паттернов
3. THE ML_Fragment_Analyzer SHALL кластеризовать дизлайкнутые фрагменты для выявления антипаттернов
4. WHEN Preference_Model обучается THEN THE System SHALL включать паттерны фрагментов как дополнительные признаки
5. THE System SHALL отображать выявленные паттерны пользователю (например: "Вам нравятся переходы от пианино к басу")
6. IF фрагментов недостаточно для анализа паттернов THEN THE System SHALL использовать только эмбеддинги

### Требование 21: Современная тёмная тема
