# Документ требований

## Введение

Персональная система музыкальных рекомендаций на основе ИИ — это веб-приложение для энтузиастов музыки, позволяющее загружать аудиофайлы, импортировать музыку с YouTube, автоматически анализировать треки с помощью ML-моделей, отмечать понравившиеся треки и фрагменты, обучать персональную модель предпочтений и получать персонализированные рекомендации.

## Глоссарий

- **Track**: Аудиозапись с метаданными и характеристиками, хранящаяся в системе
- **Fragment**: Отмеченный пользователем музыкальный момент внутри трека с временными метками (start_time, end_time)
- **Embedding**: Векторное представление аудио, извлечённое ML-моделью для поиска похожих треков
- **ML_Worker**: Python-сервис для анализа аудио и извлечения характеристик
- **FAISS_Index**: Индекс для быстрого векторного поиска похожих треков и фрагментов
- **Preference_Model**: Персональная модель предпочтений пользователя, обученная на лайках
- **BPM**: Beats Per Minute — темп музыкального произведения
- **Waveform_Player**: Аудиоплеер с визуализацией формы волны для навигации и разметки

## Требования

### Требование 1: Загрузка локальных аудиофайлов

**User Story:** Как пользователь, я хочу загружать локальные аудиофайлы, чтобы добавлять музыку в свою библиотеку.

#### Критерии приёмки

1. WHEN пользователь выбирает файл формата MP3 или WAV THEN THE Track_Uploader SHALL загрузить файл и создать запись в базе данных
2. WHEN файл загружен THEN THE Metadata_Extractor SHALL извлечь метаданные из ID3 тегов (название, исполнитель, альбом, год)
3. WHEN загружается файл неподдерживаемого формата THEN THE Track_Uploader SHALL отклонить загрузку и вернуть сообщение об ошибке
4. WHEN загрузка файла завершена THEN THE System SHALL поставить трек в очередь на ML-анализ
5. WHEN файл превышает максимальный размер (100MB) THEN THE Track_Uploader SHALL отклонить загрузку с соответствующим сообщением

### Требование 2: Импорт музыки с YouTube

**User Story:** Как пользователь, я хочу импортировать музыку с YouTube по ссылке, чтобы добавлять треки без локальных файлов.

#### Критерии приёмки

1. WHEN пользователь вводит URL видео YouTube THEN THE YouTube_Importer SHALL загрузить аудиодорожку через yt-dlp
2. WHEN пользователь вводит URL плейлиста YouTube THEN THE YouTube_Importer SHALL загрузить все треки из плейлиста
3. WHEN пользователь вводит URL канала YouTube THEN THE YouTube_Importer SHALL загрузить все видео с канала
4. WHEN импорт завершён THEN THE Metadata_Extractor SHALL извлечь метаданные из YouTube (название, автор, описание)
5. IF URL недействителен или видео недоступно THEN THE YouTube_Importer SHALL вернуть сообщение об ошибке
6. WHILE импорт выполняется THEN THE System SHALL отображать прогресс загрузки

### Требование 3: ML-анализ треков

**User Story:** Как пользователь, я хочу автоматически получать характеристики треков, чтобы использовать их для поиска и рекомендаций.

#### Критерии приёмки

1. WHEN трек добавлен в очередь анализа THEN THE ML_Worker SHALL извлечь эмбеддинги с помощью MusiCNN или EfficientAT
2. WHEN анализ выполняется THEN THE ML_Worker SHALL определить жанр трека через Essentia
3. WHEN анализ выполняется THEN THE ML_Worker SHALL определить BPM через TempoCNN
4. WHEN анализ выполняется THEN THE ML_Worker SHALL определить тональность (ключ и мажор/минор)
5. WHEN анализ выполняется THEN THE ML_Worker SHALL определить настроение (Happy, Sad, Aggressive и т.д.)
6. WHEN анализ выполняется THEN THE ML_Worker SHALL определить наличие вокала и тип звука (акустический/электронный)
7. WHEN анализ завершён THEN THE System SHALL сохранить все характеристики в базу данных
8. WHEN анализ завершён THEN THE System SHALL добавить эмбеддинг в FAISS_Index
9. IF анализ завершился с ошибкой THEN THE System SHALL пометить трек как требующий повторного анализа

### Требование 4: Хранение и управление данными

**User Story:** Как пользователь, я хочу надёжно хранить свою музыкальную библиотеку, чтобы иметь доступ к трекам и их характеристикам.

#### Критерии приёмки

1. THE Database SHALL хранить метаданные треков (название, исполнитель, альбом, год, длительность)
2. THE Database SHALL хранить ML-характеристики треков (жанр, BPM, тональность, настроение)
3. THE Database SHALL хранить фрагменты с временными метками (start_time, end_time) и связью с треком
4. THE File_Storage SHALL хранить аудиофайлы и файлы эмбеддингов
5. THE FAISS_Index SHALL синхронизироваться с базой данных при добавлении/удалении треков
6. WHEN трек удаляется THEN THE System SHALL удалить связанные файлы, фрагменты и записи из FAISS_Index

### Требование 5: Waveform-плеер и воспроизведение

**User Story:** Как пользователь, я хочу воспроизводить треки с визуализацией формы волны, чтобы удобно навигировать по аудио.

#### Критерии приёмки

1. WHEN пользователь открывает трек THEN THE Waveform_Player SHALL отобразить форму волны трека
2. WHEN пользователь кликает на waveform THEN THE Waveform_Player SHALL начать воспроизведение с выбранной позиции
3. THE Waveform_Player SHALL поддерживать zoom для детального просмотра
4. THE Waveform_Player SHALL отображать текущую позицию воспроизведения
5. THE Waveform_Player SHALL поддерживать стандартные элементы управления (play, pause, stop, громкость)

### Требование 6: Разметка музыкальных фрагментов

**User Story:** Как пользователь, я хочу отмечать понравившиеся моменты в треках, чтобы сохранять и находить похожие фрагменты.

#### Критерии приёмки

1. WHEN пользователь выделяет область на waveform THEN THE Fragment_Marker SHALL создать фрагмент с start_time и end_time
2. WHEN фрагмент создан THEN THE System SHALL сохранить его в базу данных со связью с треком
3. WHEN трек открыт THEN THE Waveform_Player SHALL отобразить все ранее отмеченные фрагменты
4. WHEN пользователь кликает на отмеченный фрагмент THEN THE Waveform_Player SHALL воспроизвести этот фрагмент
5. WHEN пользователь удаляет фрагмент THEN THE System SHALL удалить его из базы данных
6. WHEN фрагмент создан THEN THE System SHALL поставить его в очередь на извлечение эмбеддинга

### Требование 7: Лайки треков и фрагментов

**User Story:** Как пользователь, я хочу отмечать понравившиеся треки и фрагменты, чтобы система училась моим предпочтениям.

#### Критерии приёмки

1. WHEN пользователь ставит лайк треку THEN THE System SHALL сохранить отметку в базу данных
2. WHEN пользователь ставит лайк фрагменту THEN THE System SHALL сохранить отметку в базу данных
3. WHEN пользователь убирает лайк THEN THE System SHALL удалить отметку из базы данных
4. THE System SHALL отображать статус лайка для треков и фрагментов в интерфейсе
5. WHEN количество лайков достигает порога (10) THEN THE System SHALL предложить обучить модель предпочтений

### Требование 8: Обучение персональной модели предпочтений

**User Story:** Как пользователь, я хочу обучить персональную модель на моих лайках, чтобы получать релевантные рекомендации.

#### Критерии приёмки

1. WHEN пользователь запускает обучение THEN THE Preference_Model SHALL собрать все лайкнутые треки и фрагменты
2. WHEN обучение запущено THEN THE Preference_Model SHALL использовать Pairwise Ranking (BPR) алгоритм
3. WHEN обучение завершено THEN THE System SHALL сохранить веса модели
4. THE Preference_Model SHALL быть легковесной (MLP или логистическая регрессия над эмбеддингами)
5. WHILE обучение выполняется THEN THE System SHALL отображать прогресс
6. IF данных недостаточно для обучения THEN THE System SHALL уведомить пользователя о необходимости добавить больше лайков

### Требование 9: Персонализированные рекомендации

**User Story:** Как пользователь, я хочу получать персонализированные рекомендации треков, чтобы открывать музыку по своему вкусу.

#### Критерии приёмки

1. WHEN пользователь запрашивает рекомендации THEN THE Recommendation_Engine SHALL использовать обученную Preference_Model
2. WHEN рекомендации генерируются THEN THE System SHALL ранжировать треки по предсказанной релевантности
3. THE Recommendation_Engine SHALL поддерживать фильтрацию по жанру, настроению, BPM
4. WHEN модель не обучена THEN THE System SHALL предложить обучить модель или использовать поиск похожих
5. THE System SHALL отображать список рекомендаций с возможностью воспроизведения и лайка

### Требование 10: Поиск похожих треков и фрагментов

**User Story:** Как пользователь, я хочу находить треки и фрагменты, похожие на выбранный, чтобы расширять свою коллекцию.

#### Критерии приёмки

1. WHEN пользователь выбирает трек для поиска похожих THEN THE FAISS_Index SHALL найти ближайшие треки по эмбеддингам
2. WHEN пользователь выбирает фрагмент для поиска похожих THEN THE FAISS_Index SHALL найти ближайшие фрагменты
3. THE System SHALL отображать результаты поиска с оценкой схожести
4. THE System SHALL поддерживать настройку количества результатов
5. THE System SHALL поддерживать фильтрацию результатов по характеристикам (жанр, BPM, настроение)

### Требование 11: Библиотека треков

**User Story:** Как пользователь, я хочу просматривать и управлять своей музыкальной библиотекой, чтобы организовывать коллекцию.

#### Критерии приёмки

1. THE Library_UI SHALL отображать список всех треков с метаданными и характеристиками
2. THE Library_UI SHALL поддерживать сортировку по названию, исполнителю, дате добавления, BPM
3. THE Library_UI SHALL поддерживать фильтрацию по жанру, настроению, наличию лайка
4. THE Library_UI SHALL поддерживать поиск по названию и исполнителю
5. WHEN пользователь выбирает трек THEN THE System SHALL открыть Waveform_Player
6. THE Library_UI SHALL отображать статус анализа для каждого трека

### Требование 12: Экспорт данных

**User Story:** Как пользователь, я хочу экспортировать свою библиотеку в CSV, чтобы использовать данные в других приложениях.

#### Критерии приёмки

1. WHEN пользователь запрашивает экспорт THEN THE Export_Service SHALL сформировать CSV файл с метаданными и характеристиками треков
2. THE Export_Service SHALL включать в экспорт: название, исполнитель, альбом, жанр, BPM, тональность, настроение, статус лайка
3. WHEN экспорт завершён THEN THE System SHALL предоставить файл для скачивания
4. IF библиотека пуста THEN THE Export_Service SHALL вернуть сообщение об отсутствии данных

### Требование 13: Интеграция PHP и Python через очередь

**User Story:** Как разработчик, я хочу надёжную интеграцию между Laravel и Python ML-воркером, чтобы система работала стабильно.

#### Критерии приёмки

1. THE System SHALL использовать Redis для передачи задач между Laravel и ML_Worker
2. WHEN задача добавлена в очередь THEN THE ML_Worker SHALL получить и обработать её
3. WHEN ML_Worker завершает обработку THEN THE System SHALL обновить статус задачи в базе данных
4. IF ML_Worker недоступен THEN THE System SHALL сохранить задачу в очереди для повторной обработки
5. THE System SHALL поддерживать мониторинг состояния очереди

### Требование 14: Ручная корректировка характеристик

**User Story:** Как пользователь, я хочу вручную корректировать автоматически определённые характеристики, чтобы исправлять ошибки ML-анализа.

#### Критерии приёмки

1. WHEN пользователь редактирует характеристику трека THEN THE System SHALL сохранить изменение в базу данных
2. THE System SHALL позволять редактировать: жанр, BPM, тональность, настроение
3. THE System SHALL отмечать вручную отредактированные характеристики
4. WHEN характеристика отредактирована вручную THEN THE System SHALL не перезаписывать её при повторном анализе
